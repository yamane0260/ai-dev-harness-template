# Change Brief: Mutual verification and structured reviews

## Outcome

New required AI reviews use a structured record whose scope, exact repository
state, verification run, evidence hashes, verdict and blocking findings are
checked during readiness evaluation.
Human and AI findings can therefore send work back to the requirement,
implementation, test or explanation before release.

## Knowledge delta

Future maintainers must use `ai-review-record` for new review requirements and
create the record only after the tracked change is stable and verified.
The record supplies scrutiny, while a machine gate or completed MUST Human Check
still supplies decisive evidence for a MUST Claim.

## Approach and provenance

- Decision/approach: preserve disagreement until an observation identifies the correction target, and make unresolved blocking findings release blockers.

## Invariants and failure behavior

- `ai-review-record` accepts only an AI-authored record before reporting `AI_REVIEWED`; human-origin findings remain valid within that record.
- The review must match the complete revision object, including the dirty flag, and the supplied verification run and evidence file hash.
- Every covered Claim has a boundary or counterexample; unknown Claim IDs are rejected.
- Open blocking findings from either origin prevent readiness. A rejected finding needs a resolution and hashed supporting evidence.
- A valid review never replaces decisive machine evidence or a completed MUST Human Check.
- A failed required structured review blocks even when its parent Claim is SHOULD. Other SHOULD evidence gaps remain warnings.
- Historical `ai-review` requirements retain their prior existence-only behavior.

- Exact-run evidence and readiness are generated by the final `./scripts/ai/verify --harness --risk red --assurance assurance/current/CHG-20260907-MUTUAL/manifest.json` run.
- The declared structured review remains a separate required artifact below `.ai-artifacts/`.
- Final release evaluation uses `./scripts/ai/validate-assurance --manifest assurance/current/CHG-20260907-MUTUAL/manifest.json --evidence <the-reviewed-evidence.json> --release` so it evaluates the reviewed run rather than creating a new one.

## Maintenance notes

- Change the validator, review schema, template, manifest schema, policies and focused tests together when the record contract changes.
- Stabilize tracked code and durable documents before generating final evidence. Any tracked correction invalidates the previous review and requires a new run.
- Keep `ai-review` as a compatibility path; use `ai-review-record` for new manifests.
