# Change Brief: Responsibility-transfer V3 foundation

## Outcome

The harness now treats inspectable responsibility transfer—not the mere presence of generated code or a green test command—as the completion model for non-trivial AI-led work.

## Knowledge delta

Future maintainers must distinguish committed proof obligations (`assurance/`) from exact-run evidence (`.ai-artifacts/`), and must use Claim facets plus Human Checks instead of a single trust score.

## Approach and provenance

- Decision/approach: add repository-native JSON Assurance records, exact-revision evidence, a derived relationship index, domain-adaptive explanation policy, and a sanitized agent-event contract before building a graphical Explorer.
- Provenance: `RECORDED`.
- Evidence: `docs/specs/harness-v3-responsibility-transfer.md`, `docs/decisions/2026-09-04-assurance-as-repository-data.md`, and `assurance/changes/CHG-20260904-V3/manifest.json`.

## Where it lives

- `PROJECT_MAP.md`: human starting point and folder/source-of-truth map.
- `assurance/`: committed Claims, evidence requirements, Human Checks, and uncertainty.
- `ai/policies/assurance.md`: readiness semantics.
- `scripts/ai/validate-assurance`: relationship and readiness validator.
- `scripts/ai/record-evidence`: exact-run evidence writer.
- `scripts/ai/build-project-index`: rebuildable graph/read model.
- `ai/policies/adaptive-explanation.md` and `explain-system`: prose-on-demand behavior.
- `ai/policies/agent-control.md` and agent-event utilities: trace contract and sanitized summaries.

## Invariants / failure behavior

- AI review never becomes machine proof.
- A required gate that is N/A/missing/failing/stale cannot support a MUST Claim.
- Pending/failed MUST Human Checks prevent release readiness.
- Generated evidence/index/traces remain outside Git.
- Template `verify` compatibility remains, while `--harness` is explicitly not product evidence.
- Trace completeness is stated, never inferred.
