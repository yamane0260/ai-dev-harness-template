## Interaction conventions

Use this precedence unless the product has an explicit reason to differ:

1. Existing product pattern.
2. Existing design-system/component pattern.
3. Platform convention.
4. Established convention for this product category.
5. New custom interaction pattern.

Visual identity may be distinctive; common controls and workflows should remain predictable unless deviation materially improves the task.

## Settings model

- Prefer sensible defaults over forcing configuration.
- Group settings by user goal, not implementation subsystem.
- Put frequent/high-value settings before rare/advanced settings.
- Separate dangerous/destructive actions from ordinary preferences.
- Do not move task-specific controls into global settings merely because they are configurable.
