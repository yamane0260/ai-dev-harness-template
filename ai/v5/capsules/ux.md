# UX Capsule

Load only for material user-facing interaction.

Check the real task flow rather than visual polish alone:

- can the intended user discover what to do next without hidden knowledge?
- are loading, empty, error, disabled, and success states coherent?
- does navigation/state behavior match surrounding product conventions?
- does the implementation preserve keyboard/accessibility semantics where applicable?
- are destructive or consequential actions distinguishable and recoverable?
- does the change reduce operator/user work rather than merely expose internal implementation structure?

If a product tradeoff is genuinely subjective or changes workflow policy, escalate it to the supervisor instead of silently deciding it.
